## What must not change

- **The ownership model.** `SYNC/` in `.gitignore`, the items in the user's folder, the database
  local, nothing pushed to a project. Verified: `git check-ignore -v SYNC SYNC/ITEMS/skills/foo`
  matches `.gitignore:53:SYNC`, and the pattern does not over-match (`docs/SYNC.md` and `mySYNC`
  are not ignored). The user's `SYNC` folder is theirs; this design must not reintroduce a
  committed copy.
- **The naming separation.** A global item and a project item must never share a name, because
  the harnesses disagree on which one wins. Confirmed at the primary source: Claude Code resolves
  a same-named skill as "Enterprise over personal, and personal over project", but resolves a
  same-named **subagent** with the project scope at priority 3 and the user scope at priority 4 —
  opposite orders for the same harness. The `global` reserved slug exists for this reason and
  must survive (see GI-03 for where the guard belongs).
- **The three-auditor, two-of-three, three-round rule, and the degraded-round record.** It is the
  owner's flight-computer rule, it is consistent with the AGENTS.md bullet, and the design's
  outcome table plus the dissent step is a sound implementation of it. A confirmed lone finding
  becoming a fix is the part that makes disagreement useful; keep it.
- **The "proposed, never pushed" principle.** No global item reaches a project without that
  project's decision, and the adoption audit precedes the change.
- **The explicit wrapper instead of inheritance.** No skill standard has `extends`, so the wrapper
