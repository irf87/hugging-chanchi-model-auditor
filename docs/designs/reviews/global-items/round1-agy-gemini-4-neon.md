## What must not change

- **Ownership boundary and `.gitignore`:** User-owned global items and configuration live in gitignored `SYNC/` (`SYNC/ITEMS/`, `SYNC/config/`), recommended as a symlink to cloud storage or a private git repo; SQLite stays local and is never synced through a cloud folder.
- **Naming and no-shadowing invariant:** Reserved `global` slug, `<item>-chanchi-global-<name>` for global items, `<item>-chanchi-<slug>-<name>` for project items, and explicit local wrappers instead of same-name shadowing across harnesses.
- **Core audit policy:** Three auditors per round from disjoint model families when available, roster fallback with `degraded` tracking when unavailable, 2-of-3 acceptance, hard cap of 3 rounds followed by human escalation with a disagreement report, and independent brief isolation per auditor.
- **Thin stdlib CLI architecture:** `chanchi` decides, validates, renders, and records without launching harnesses or adding runtime dependencies; `harnesses.py` centralizes per-harness metadata so adding future harnesses (Cursor, Codex) stays a single-row extension.
- **Voluntary adoption & lifecycle primitives:** Proposed-never-pushed model (`adopt`, `wrap`, `decline`, `deprecate`), semantic versioning + `CHANGELOG.md` + SHA-256 content hashes, append-only `retired.json` tombstones, and the evidence-backed Adopt / Adapt / Avoid table.
- **Six-phase incremental rollout:** Auditing first (Phase 1), `SYNC/` + mirror second (Phase 2), capture/propose + first global `herdr` skill third (Phase 3), adoption fourth (Phase 4), project items fifth (Phase 5), and fractal replication sixth (Phase 6).
